================================================================
  Threads AutoPoster - 他のPCでのご利用手順マニュアル
================================================================

このフォルダ（dist\ThreadsAutoPoster または ZIP解凍フォルダ）は、
別のWindows PC（ご自宅のPC、別の作業PC、ノートPC、VPSなど）に
コピーしてそのまま動かすことができます！

----------------------------------------------------------------
【STEP 1: 他のPCへのフォルダの持っていき方】
----------------------------------------------------------------
1. 「dist\ThreadsAutoPoster」フォルダ（または解凍フォルダ一式）を、
   USBメモリ、Googleドライブ、OneDrive等にコピーします。
2. 別のPCのデスクトップやドキュメントなど任意の場所に貼り付けます。

----------------------------------------------------------------
【STEP 2: 別のPCでの初回セットアップ（1回だけ・1分）】
----------------------------------------------------------------
別のPCで初めて動かすときは、Pythonやブラウザが入っていない場合があります。
フォルダ内の以下を実行してください:

  👉 「0_他のPCでもすぐ動く環境作成.bat」をダブルクリック！

  ※自動で必要なPython環境やPlaywrightブラウザがインストールされます。
  ※すでにPythonが入っているPCの場合は数秒で確認完了します。

----------------------------------------------------------------
【STEP 3: 起動方法】
----------------------------------------------------------------
・「x_auto_dm_gui.exe」（または「ThreadsAutoPoster.exe」）をダブルクリック！
  （または「start_gui.bat」でも同様に起動できます）

----------------------------------------------------------------
【重要：Hyonixなど別のVPS・他PCへ移行するときの「電話番号確認ロック」対策】
----------------------------------------------------------------
別のHyonix VPSや他PCへ移してそのまま起動すると、Meta側で「不審な端末・IP移動」と判定され
電話番号確認（SMS認証）ロックがかかることがあります。主な原因は以下の通りです：

1. グローバルIPアドレスの急変（Hyonix VPS #1 → VPS #2 など別データセンターIPへの移動）
2. Windows DPAPI暗号化キーの違いにより、コピーしたChromeのCookiesファイルが復号できない
3. 旧VPSと新VPSで同じアカウントを同時稼働させてセッション競合する
4. 別PC移行直後に最初から自動ログイン（ID/PW）や連続アクセスが走る

● 最新版での自動防御＆対策機能：
  ・【プロキシ固定に対応】「アカウント情報.xlsx」の【プロキシ】列に固定プロキシ
    （推奨：住宅IP / ISPプロキシ / Sticky Residential Proxy）を設定すると、
    Hyonixの別VPSへ移っても「同じIP」から接続できるため電話番号確認を大幅に回避できます。
    対応書式: http://user:pass@ip:port / socks5://user:pass@ip:port / ip:port:user:pass / ip:port
  ・【別PC移行の自動検知＆DPAPI安全再バインド】fingerprint.json でPC変更を自動検知し、
    別PCで復号できない古いSQLite Cookieだけを安全に初期化しつつ、実ブラウザ由来の
    デバイスCookie（datr / mid / ig_did）と portable_session.json を壊さずに再バインドします。
  ・【初回ウォームアップ】別PCでの初回起動時は15秒前後の自然なフィード閲覧を行ってから投稿します。
  ・【SMS認証検知時の即安全停止】チェックポイント画面を検知したら即ブラウザを終了し、
    自動で「無効」化して連打による本凍結を防ぎます。

● 安全なHyonix別PC移行手順（推奨）：
  1. 旧Hyonixサーバー上の ThreadsAutoPoster とブラウザを完全に終了する。
  2. 別IP環境になる場合は、できれば「アカウント情報.xlsx」の【プロキシ】列に
     住宅プロキシ（Sticky Residential Proxy）を設定する。
  3. フォルダ一式（特に「chrome_profiles/<アカウントID>/」と「アカウント情報.xlsx」
     「<アカウントID>.xlsx」）を新Hyonixサーバーへコピーする。
  4. 新サーバーではまず「0_他のPCでもすぐ動く環境作成.bat」を実行する。
  5. 初回はすぐに連続自動投稿せず、手動で1回ブラウザを開いて（profile_launcher.py等）
     タイムラインが正常に見られるか確認してから自動投稿を開始するとさらに安全です。

※もしすでに電話番号確認ロックがかかってしまった場合は、
  新PCでログイン試行を繰り返さず、いったんツールを止めて（自動無効化されます）
  「元々正常に動いていたHyonix PCのIP」または「設定した固定プロキシ環境」の手動ブラウザから
  SMS認証を完了させ、その後「アカウント情報.xlsx」を「有効」に戻してください。

----------------------------------------------------------------
【ログイン・設定について】
----------------------------------------------------------------
● chrome_profiles / portable_session.json による引き継ぎ（推奨）:
  同PC内、または「profile_launcher.py」で保存した「portable_session.json」＋
  プロキシ設定を組み合わせることで、別PCでも安全にセッションを引き継げます。
  ※「アカウント情報.xlsx」の sessionid だけでもログイン復元は可能ですが、
    別VPSの異なるデータセンターIPから突然アクセスするとSMS認証が出やすくなるため、
    重要なアカウントは【プロキシ】列または portable_session.json の併用を推奨します。

● アカウントごとの個別設定:
  各「<アカウントID>.xlsx」に記入されている
  ・ポスト間隔（例: 120〜360分）
  ・実行時間帯 / 曜日 / 各ポスト横の投稿時間・曜日
  ・投稿モード（0:上から順, 1:ランダム）
  がそのまま別のPCでも適用されます。

● Chromeプロファイル:
  各PC内の「chrome_profiles/<アカウントID>」フォルダに自動生成・保存されます。
